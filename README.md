# Laravel Labs

Live site: [Laravel Labs](https://thanhson99.github.io/laravel-labs/index.html)

> A personal learning portal that turns scattered PHP and Laravel notes into a structured system.  
> Built to help learners move from fundamentals to real-world engineering thinking: architecture, debugging, security, performance, DevOps, interview prep, and AI-assisted coding.

---

## What is this repository?

This repository is not just a collection of snippets or demo projects.

It is a long-term **learning system** for:
- understanding PHP before going deeper into Laravel
- learning Laravel through connected topics instead of isolated tutorials
- reviewing technical concepts with real examples, code blocks, and applied context
- preparing for interviews across multiple seniority levels
- learning how to use AI in coding without losing engineering judgment

The goal is simple:

**learn with structure, revise with context, and connect theory to real work.**

---

## What can you learn here?

### PHP Foundations
This part covers the base layer needed to read Laravel code with confidence:
- variables, functions, arrays, loops, conditions
- OOP, dependency injection, coupling, separation of concerns
- HTTP basics, request/response thinking, sessions, cookies, headers
- the mental model behind backend programming

### Laravel in Depth
This is the main body of the portal. It goes far beyond “how to build CRUD”.

Topics include:
- app structure
- Composer and vendor mindset
- PHP commands and Artisan workflows
- Node, npm, and the frontend layer around Laravel
- Blade, components, and server-rendered UI
- database, Eloquent, queries, and migrations
- request flow from browser to response
- Dependency Injection, service container bindings, architecture, and service boundaries
- auth, security, policies, sessions, Sanctum, and access control
- API integration, webhooks, retries, and idempotency
- files, uploads, storage, media handling, and S3 thinking
- queue, events, async workflows, and workers
- performance, cache, search, and runtime bottlenecks
- realtime UX and broadcasting
- testing, debugging, and code quality
- Sail, environment setup, deployment, and operational thinking
- maintenance, upgrades, and long-term system health

### Interview Preparation
The interview branch is organized by level:
- Fresher
- Junior
- Intermediate
- Senior
- Master
- DevOps

It is designed to cover more than short theory answers.  
It includes:
- foundational questions
- scenario questions
- problem-solving questions
- teamwork and communication questions
- ownership and decision-making questions
- hard production and systems questions for higher levels

### Vibe Coding
This branch focuses on AI-assisted development from a practical engineering perspective.

It includes:
- Prompting
- AI CRUD
- AI Review
- AI Runtime

This is not about blindly trusting AI.

It is about learning:
- how to prompt clearly
- how to scope AI output
- how to review generated code
- how to spot hallucinations and unsafe assumptions
- how to keep runtime, deployment, and production changes under control

### Glossary
The glossary is built to help beginners and working developers decode technical language.

It covers:
- web and browser terms
- backend and OOP terms
- Laravel-specific concepts
- database and API vocabulary
- security and DevOps language
- architecture and systems thinking
- AI-assisted coding vocabulary

It also includes:
- real bug examples
- “often confused with” explanations
- cross-links to deeper topic pages

### Practice
This area turns passive reading into action:
- mini practice tasks
- bug labs
- review checklists
- study rhythm ideas
- practical next steps after reading theory
- runnable Hub workbenches that connect static notes to real Laravel code
- Dependency Injection refactor drills for replacing manual `new` calls with container-resolved collaborators

## Why this portal exists

A lot of learners hit the same problems:
- they read too many disconnected tutorials
- they learn syntax without understanding structure
- they can follow CRUD but get lost in real projects

It is built around the idea that good technical learning should connect:
- **fundamentals**
- **framework knowledge**
- **real-world failure modes**
- **engineering tradeoffs**
- **communication and decision-making**

## Learning style behind this project

This portal is intentionally designed around a few principles:

- **Layered learning**  
  Start from basics, then move into architecture, runtime, and systems thinking.

- **Cross-linked knowledge**  
  Terms should connect to real pages. Concepts should not stay isolated.

- **Code where it matters**  
  Examples, commands, and snippets are included so theory does not stay abstract.

- **Real-world framing**  
  Topics are explained with bugs, failure modes, performance concerns, security risks, and maintainability tradeoffs.

- **Long-term maintainability**  
  The portal is meant to grow as a knowledge base, not remain a static note dump.

## Included Laravel labs

The repository also contains several Laravel projects that support the learning portal and give real code context:
- `hub` - aggregate Laravel practice app that reads `data/**`, exposes learning/practice pages, and documents environment-driven config through `hub/.env.example`
- `breeze`
- `chirper`
- `jetstream`
- `sail`

These help connect the theory in the portal to actual Laravel source code, structure, configuration, and behavior.

### Hub configuration notes

The `hub` app keeps environment-specific values out of services, views, and JSON content:
- `LABS_CONTENT_PATH` points the app to the static portal JSON content.
- `HUB_RUNTIME_BASE_URL`, `HUB_PORT`, and `HUB_INTERNAL_PORT` control local and Docker runtime URLs/ports.
- configuration-practice artifact IDs and auth timing values are documented in `hub/.env.example`.

Do not commit `hub/.env`; use `hub/.env.example` as the shareable contract.
