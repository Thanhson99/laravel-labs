# Static Site Architecture

This document explains how the static portal behaves at runtime. Read this before changing `assets/site.js`, `assets/shell.js`, `partials/**`, navigation, search, progress, or frontend behavior.

## Runtime Components

The static portal has three main layers:

- Page wrappers in `index.html` and `sites/**/*.html`.
- Shared shells in `partials/*.html`.
- Runtime rendering and behavior in `assets/shell.js` and `assets/site.js`.

The wrappers are intentionally thin. They should only provide:

- document metadata
- CSS link
- `data-page`
- `data-site-root`
- script tags for `shell.js` and `site.js`

## Shell Loader

`assets/shell.js` reads:

- `document.body.dataset.page`
- `document.body.dataset.siteRoot`

Then it chooses a partial with `resolveShellName(pageKey)` and fetches:

```text
{SHELL_SITE_ROOT}/partials/{shellName}.html
```

The loaded markup is inserted into `#appShell`. If `#appShell` does not exist, `shell.js` creates it and prepends it to `body`.

`shell.js` exposes:

```javascript
window.__shellReady
```

`assets/site.js` waits for this promise before rendering page content.

## Main Renderer

`assets/site.js` owns:

- language selection
- theme selection
- page data loading
- topic data loading
- rendering shell placeholders
- breadcrumbs
- header navigation
- global search
- reading dock
- page progress
- roadmap filters
- PHP keyword directory
- topic switchers
- resume prompts
- code copy buttons

The main entrypoint is `init()`.

Renderer contract for learning content:

- JSON content chooses a supported shape; renderers decide the visual structure.
- Major sections render as `.panel` and should not become card surfaces.
- Repeated related content renders through shared components: content cards, link cards, bullet-list items, interview QA cards, PHP phases/modules/examples/questions, or roadmap cards.
- Renderer helpers should not emit one-off classes just to fix one page unless the new class represents a reusable content shape.
- Renderer helpers that add nested lists must preserve plain nested bullet styling so child bullets do not inherit outer card surfaces.
- Renderer helpers that add code-copy buttons must pair them with code-block padding rules for desktop and mobile.

The render decision tree is:

- `landing` -> `renderLanding`
- `php` or `php-*` -> `renderPhp`
- `laravel` -> `renderLaravelOverview`
- `laravel-*` -> `loadLaravelSection` then `renderLaravelTopic`
- `interview` -> `renderInterviewOverview`
- `interview-*` -> `loadInterviewSection` then `renderInterviewTopic`
- `vibe-coding` or `videos` -> `renderVideoOverview`
- `vibe-*` or `video-*` -> `loadVideoSection` then `renderVideoTopic`
- other pages -> `renderDetail`

## Page Data Loading

Language-specific root content is loaded from:

```text
data/site-content.{language}.json
```

The active language comes from localStorage key:

```text
laravel-labs-language
```

Fallback language is `en`.

Topic data is loaded from:

- `data/laravel/{topic}.{language}.json`
- `data/interview/{topic}.{language}.json`
- `data/vibe-coding/{topic}.{language}.json`
- `data/php/{level}.{language}.json`

The topic key is derived from the page key by removing the family prefix:

- `laravel-auth-security` -> `auth-security`
- `interview-senior` -> `senior`
- `vibe-ai-review` -> `ai-review`
- `php-advanced` -> `advanced`

## Navigation

Central navigation is generated by `createHeaderNav(data, language, pageKey)`.

URL resolution should go through:

```javascript
getPageHref(pageKey)
```

`getPageHref` canonicalizes legacy page keys with `LEGACY_PAGE_KEY_MAP`, then checks `PAGE_PATHS`, then falls back to:

```text
{SITE_ROOT}/sites/{key}.html
```

Avoid hardcoded relative links inside partials and render helpers when a page key exists.

Hub workbench links in JSON content should use the `{{HUB_BASE_URL}}` token instead of a fixed host and port. `assets/site.js` resolves that token from `data-hub-base-url` on the page body or `window.LARAVEL_LABS_HUB_BASE_URL`; if neither is set, the link resolves as a same-origin path.

## Breadcrumbs

Breadcrumbs are generated by:

```javascript
renderBreadcrumbTrail(data, language, pageKey)
```

Breadcrumb labels come from:

- navigation labels in root data
- current rendered page title

Breadcrumb links use `getPageHref()` or `SITE_ROOT`.

## Theme

Theme is stored in localStorage key:

```text
laravel-labs-theme
```

Accepted value:

- `dark`

Any other value behaves as `light`.

Theme is applied through:

```javascript
document.body.dataset.theme = theme
```

## Progress

Content progress is stored in:

```text
laravel-labs-content-progress
```

Roadmap progress is stored in:

```text
laravel-labs-roadmap-progress
laravel-labs-roadmap-collapsed
```

Progress UI is generated by `renderPageUtilityBar` and synchronized by `syncContentProgressUi`.

Progress IDs depend on:

- page key
- section key
- item index
- slugified item title

Changing anchors, item order, or titles can reset user progress.

## Global Search

Global search is built lazily when the search panel opens.

Important functions:

- `collectSearchText`
- `createSearchDoc`
- `createPageSearchDocs`
- `createTopicSearchDocs`
- `buildSearchIndex`
- `scoreSearchDoc`
- `createSearchSnippet`
- `bindGlobalSearch`

Search indexes:

- root page data
- page menus
- page sections
- Laravel topic JSON
- Interview topic JSON
- Vibe Coding topic JSON
- PHP level JSON

Search index is cached per language in `SEARCH_INDEX_CACHE`.

## PHP Keyword Directory

PHP level pages have a keyword jump directory generated from inline backtick keywords and titles.

Important functions:

- `extractInlineKeywords`
- `collectPhpKeywords`
- `renderPhpKeywordDirectory`
- `bindPhpKeywordJumps`
- `animateWindowScroll`

The keyword directory depends on stable generated IDs from `withPhpIds`.

## Roadmap Features

The roadmap page uses the `mindmap` section type.

Important functions:

- `createMindmapSection`
- `bindRoadmapFilters`
- `getRoadmapProgress`
- `getRoadmapCollapsed`
- `normalizeRoadmapBranchKey`

Roadmap supports:

- search filter
- tone filter
- branch collapse
- learning progress
- study mode

## Rendering Safety

`assets/site.js` uses `innerHTML` heavily. The safe helpers are:

- `escapeHtml(value)`
- `formatRichText(value)`

Use `escapeHtml` for plain text. Use `formatRichText` only when inline backtick highlighting should be preserved.

Do not insert JSON-backed text directly into `innerHTML` unless it is intentionally trusted markup. Most content is not intended to be raw HTML.

Attributes need escaping too. This includes:

- `href`
- `id`
- `aria-label`
- `placeholder`
- `data-*`

## Known Couplings

- `data-page` must match renderer logic and `PAGE_PATHS`.
- Partial IDs must match `document.getElementById` calls.
- Menus in `data/site-content.*.json` drive topic navigation and search.
- PHP levels are configured in multiple places: `PHP_LEVELS`, `PAGE_PATHS`, `PHP_LEVEL_PAGE_MAP`, `PHP_HEADER_MENU`, data files, and page wrappers.
- Laravel, Interview, and Vibe topic pages derive JSON file paths from page keys.
