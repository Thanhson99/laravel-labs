# Definition Of Done

Use this file to decide whether a task is complete. Apply the relevant section based on the task type.

## Universal Done Criteria

A task is not done until:

- The requested scope is implemented or clearly documented as blocked.
- The change is limited to the intended files and behavior.
- Existing user changes are preserved.
- Relevant docs are updated if the change adds durable knowledge.
- Verification was run, or missing tooling/blockers are clearly reported.
- `git status --short` was checked.
- The final response states what changed and what could not be verified.

## Static Site Code Done

Applies to:

- `assets/**`
- `partials/**`
- `sites/**`

Done criteria:

- Page shell still loads.
- Required IDs in partials match renderer code.
- Links use `SITE_ROOT` or `getPageHref()` when possible.
- JSON-backed text is escaped before `innerHTML`.
- EN/VI language switching still works for touched pages.
- Theme switching still works for touched pages.
- Global search still opens if search-related code changed.
- Progress/localStorage behavior still tolerates malformed storage.
- Responsive behavior was considered for mobile and desktop.
- Renderer changes preserve the shared content-block contract from `docs/design-system.md`: major sections stay as `.panel`, repeated content stays inside card/list/block components, and nested lists remain visually plain.
- Code blocks with copy buttons were checked so text does not render underneath the copy button on desktop or mobile.

Verification:

- Parse relevant JSON.
- Run a local HTTP server and smoke test if tooling is available.

## JSON Content Done

Applies to:

- `data/**`

Done criteria:

- JSON parses.
- English and Vietnamese files remain aligned when paired.
- Anchors remain stable unless intentionally changed.
- Item order remains stable if progress IDs should be preserved.
- Content follows `content-quality-standards.md`.
- Content belongs in the correct learning area from `content-taxonomy.md`.
- New content uses an existing renderer-supported shape from `docs/data-schema.md` before any writing begins.
- Related learning items are not left as loose paragraphs when they belong in default cards, `type: "list"`, `type: "links"`, or PHP `modules`/`phases`.
- Code snippets are safe and relevant.
- No raw HTML is introduced unless the renderer expects it.
- Raw HTML is never used to force spacing, borders, color, card layout, or headings.
- If list items use `bullets`, those bullets are short supporting details and do not duplicate the parent item title/body structure.

Verification:

```powershell
Get-ChildItem data -Recurse -Filter *.json | ForEach-Object {
  $file = $_.FullName
  try {
    Get-Content -Raw -LiteralPath $file | ConvertFrom-Json | Out-Null
  } catch {
    Write-Output ("DATA JSON FAIL: " + $file + " :: " + $_.Exception.Message)
  }
}
```

## CSS/UI Done

Applies to:

- `assets/css/**`
- markup generated by `assets/site.js`
- `partials/**`

Done criteria:

- Visual style stays consistent with `design-system.md`.
- Light and dark themes are considered.
- Mobile and desktop layouts are considered.
- Long Vietnamese labels do not overflow obvious controls.
- New components use existing CSS variables.
- New content surfaces reuse the existing white-surface card/list/block treatment instead of adding a page-specific style.
- CSS selectors do not accidentally style nested supporting lists as outer cards.
- Typography hierarchy remains clear: section heading, block/card title, supporting description, nested details.
- Accessibility attributes are present for interactive controls.
- No unnecessary new color system or UI library is introduced.

## Laravel Code Done

Applies to:

- `breeze/**`
- `chirper/**`
- `jetstream/**`
- `sail/**`

Done criteria:

- Target app version and structure were checked in `laravel-labs-inventory.md`.
- Principal Laravel rules were applied for non-trivial code.
- Controllers are thin.
- Validation is in Form Requests where appropriate.
- Business logic is in Services/Actions.
- Reusable query/database logic is in Repositories/Queries.
- Authorization is handled with policies/gates/Form Request `authorize()` where needed.
- Multi-step writes use transactions.
- Queries avoid obvious N+1 issues.
- Secrets are not hardcoded.
- Tests were added or updated for changed behavior when practical.
- PHPDoc is present for new AI-generated Laravel classes and methods.
- Code follows PSR-12 style.

Verification:

- Run target app tests if PHP/Composer are available.
- If tests cannot run, state which commands should be run later.

## Documentation Done

Applies to:

- `docs/**`
- `AGENTS.md`
- `README.md`

Done criteria:

- New docs are linked from `docs/README.md` when they are durable.
- New mandatory rules are linked from `AGENTS.md`.
- Conflicting rules are addressed in `rule-precedence.md`.
- Durable findings are recorded in `ai-change-log.md`.
- Wording is concise and actionable.
- Docs do not duplicate large sections unnecessarily.

## Review Done

For code review tasks:

- Findings come first.
- Findings are ordered by severity.
- Each finding references file/line when possible.
- Each finding explains risk and concrete fix.
- Missing tests are called out.
- If no issues are found, say so clearly and mention residual risk.

## Blocked Done

If a task cannot be fully completed:

- Explain the blocker.
- State what was completed.
- State what remains.
- Provide exact commands or files needed to continue.
- Do not claim verification passed if it did not run.
